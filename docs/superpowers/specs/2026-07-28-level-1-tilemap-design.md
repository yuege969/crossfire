# Level 1 TileMapLayer 关卡设计

**日期：** 2026-07-28  
**状态：** 已确认（用户授权按专业判断完成）

## 目标

使用现有 `subway.png` 与 `walls.png` 图集，将 `Level1` 搭建为一张可从左向右完整通行的废弃地铁维护区关卡。关卡长度为 6–8 个当前摄像机屏幕，兼顾射击空间与中等难度的平台跳跃。

## 范围

- 完成背景、背景细节、实体地形和前景四个 `TileMapLayer`。
- 为实体地形配置准确的物理碰撞。
- 设置安全出生点、主路线、低层绕行路线和明确的终点标识。
- 保留现有玩家、子弹容器及其脚本行为。
- 不加入敌人、机关、坠落死亡、检查点或重生系统。

## 关卡结构

关卡采用约 256×30 个 16 像素网格，即约 4096×480 像素的横向空间。按推进节奏分为六段：

1. **起点站台：** 宽阔安全区域，用标牌和绿色方向灯建立前进方向。
2. **维护通道：** 短平台和低矮掩体，教授基础跳跃。
3. **设备房：** 第一处开阔战斗空间，提供上下两条可通行路线。
4. **断裂通道：** 中等跨度缺口；失败会落入低层维护道，不会掉出场景。
5. **升降维护区：** 交错高低平台与第二处开阔战斗空间。
6. **出口站台：** 路线重新汇合，使用绿色灯光和出口标识形成视觉终点。

主路线始终由水平结构和绿色导向元素向右引导。支线只提供位置变化，不制造死路。

## 视觉分层

- `BGLayer`：连续的暗绿色砖墙、墙框和大面积墙面填充，覆盖完整可见范围。
- `BGDetailLayer`：管线、支架、设备面板、海报、箱体和导向标牌；避免影响可通行轮廓的辨识。
- `CollisionLayer`：地板、平台、立柱和下层维护道。只在该层启用碰撞。
- `FGLayer`：少量顶部管线、近景支架和边缘遮挡，避开玩家主要活动区域。

所有层共享同一 16×16 `TileSet`。绘制顺序为背景、背景细节、实体、实体角色、前景。

## 碰撞与可玩性

- `TileSet` 增加一个 2D 物理层。
- 实体地形使用完整 16×16 方形碰撞图块，视觉表面与碰撞网格对齐。
- 主路线平台最小宽度为 4 格；常规跳跃缺口为 2–4 格。
- 垂直落差不超过玩家当前跳跃能力；所有低层路线都能通过阶梯式平台回到主路线。
- 左右边界和最低层由实体地形封闭，玩家不会从地图边缘或底部掉出。
- 玩家出生在第一段安全地面上方，不与碰撞体重叠。

## 素材使用原则

- `walls.png` 作为主要建筑结构，优先使用大块墙体、砖墙、横梁和绿色出口结构。
- `subway.png` 作为细节图集，使用管线、箱体、海报、设备和箭头标牌打破重复感。
- 不拉伸像素素材；保持 nearest 过滤与整数网格定位。
- 大型复合图块按原图集相邻关系连续铺设，避免切片错位。

## 验收标准

- Godot 4.7 可以无解析错误地载入并运行 `level_1.tscn`。
- 玩家可以从出生点沿主路线或低层绕行路线抵达终点区域。
- 地面、平台、边界和低层通道均有碰撞；背景与前景装饰不阻挡玩家。
- 四个 `TileMapLayer` 都有明确职责并包含实际地图内容。
- 关卡宽度符合 6–8 个当前摄像机屏幕，画面没有大面积透明空洞或明显错误切片。
- 不覆盖 `player.tscn` 中现有的用户未提交改动。
